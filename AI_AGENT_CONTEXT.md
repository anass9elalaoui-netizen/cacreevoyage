## 🏗 Tech Stack & Architecture

### Core Technologies
- **Framework**: [Next.js 15](https://nextjs.org/) (App Router) & React 19
- **CMS**: [Payload CMS v3.43](https://payloadcms.com/) (Headless CMS integrated directly into Next.js)
- **Database**: PostgreSQL (via `@payloadcms/db-postgres`)
- **Storage**: S3 API (via `@payloadcms/storage-s3`) for media/assets
- **Styling**: Tailwind CSS & Vanilla CSS modules
- **Animations & Scrolling**: [Framer Motion](https://www.framer.com/motion/) and [Lenis](https://lenis.studiofreight.com/) (smooth scrolling)
- **Language**: TypeScript

### Directory Structure
- `src/collections/`: Payload CMS Data Models (Entities like `Tours`, `Destinations`, `Articles`, `Media`, `Orders`, etc.)
- `src/globals/`: Payload Global Configs (Singletons like `SiteSettings`, `HeroPortalConfig`, etc.)
- `src/components/`: Reusable React components (UI elements, interactive blocks).
- `src/app/(frontend)/`: The Next.js frontend routes (the public-facing website).
- `src/payload.config.ts`: The central configuration for Payload CMS, defining plugins, editor settings (Lexical), and storage credentials.

### 🌐 Architecture: Website vs. Admin Panel
This project uses **Payload CMS 3.0+**, which is deeply integrated directly into the Next.js App Router. Instead of having a separate backend repository or server, everything runs within the same unified Next.js application.

1. **The Admin Panel (Backend)**: 
   - Accessed via `/admin` (automatically generated by Payload based on `payload.config.ts`).
   - Content managers use this intuitive interface to create/edit Tours, Destinations, modify Site Settings, and upload Media.
   - It connects to a **PostgreSQL** database to store structured data and uses an **S3 API** to store uploaded images/videos.
   - Developers define the structure of this admin panel by creating schemas in `src/collections/` and `src/globals/`.

2. **The Website (Frontend)**:
   - Accessed via standard frontend routes like `/`, `/sur-mesure`, `/destinations` (located inside `src/app/(frontend)/`).
   - Because Payload lives inside Next.js, the frontend fetches data securely on the server side using the Local API (`getPayload()`), avoiding external HTTP requests and minimizing latency.
   - The frontend focuses strictly on the user experience, utilizing React Server Components for SEO/performance and Client Components (`'use client'`) for advanced kinetic animations (like the Hero Portal).

## 🎨 Advanced Techniques: The "Hero Portal"

One of the standout features of this project is the **PortalHero** (`src/components/hero/PortalHero.tsx`), which provides an ultra-premium, cinematic scroll-scrubbing effect. If you need to modify this or build something similar, here is the exact technique we use:

### The "Scroll-Scrubbing Canvas" Technique
Instead of playing a standard `<video>` (which behaves poorly when scrubbed by scroll), we extract a video into individual JPEG frames (e.g., `ezgif-frame-001.jpg` to `142.jpg`) and render them on an HTML5 `<canvas>` as the user scrolls.

**Key Implementation Details:**
1. **Frame Preloading Strategy**: To prevent a massive initial payload, we preload the first batch of frames (e.g., 20 frames) using a `Promise.all` approach so the initial view paints immediately. The remaining frames are then silently downloaded in the background.
2. **Scroll Tracking & Physics**: We use Framer Motion's `useScroll` to get the page scroll progress, but we don't map it directly. We pipe it through `useSpring` (stiffness: 50, damping: 40) to apply physical damping. This guarantees an ultra-fluid, momentum-based playback—even if the user scrolls using a clunky mouse wheel.
3. **Optimized Render Loop**: 
   - A `useMotionValueEvent` listens to the spring value and maps it to a frame index (1 to N).
   - We use `requestAnimationFrame` (and cancel previous RAFs) to call our `drawFrame()` function.
   - We cache the `lastDrawnFrame` to aggressively kill redundant canvas draws.
4. **Canvas `object-fit: cover` Math**: Since native canvas doesn't support CSS `object-fit`, the `drawFrame` function mathematically calculates the aspect ratio of the image versus the viewport and draws it scaled and centered so it perfectly fills the screen without distortion.
5. **Bulletproof Frame Fallbacks**: If the user scrolls fast and requests frame 80, but it hasn't loaded yet, the drawing logic falls back to the *nearest available loaded frame*. This completely eliminates "flashing" or blank canvases.
6. **Kinetic Text Synchronization**: We built a custom `<KineticScrollText>` component. Instead of animating based on scroll percentage, it animates based on the *exact frame index* (e.g., appear at frame 50, peak at 65, fade out at 105) utilizing Framer Motion's `useTransform` and GPU-accelerated CSS properties (`opacity`, `transform: translateY`, `filter: blur`).
7. **The Scrolling Container**: The parent div is set to `height: 600vh` to create a massive scrollable area. Inside it, a child div is `sticky h-screen`, locking the canvas and text overlays in the viewport while the user scrolls down the "600vh" track.

## 📝 Guidelines for AI Agents

When working on this project, adhere strictly to the following rules:

1. **Aesthetics are Critical**: This is a premium luxury travel brand. All new frontend components must utilize high-end design principles—smooth gradients, proper typography (sans and serif mixes), glassmorphism where appropriate, cinematic shadows, and micro-animations. **Never implement generic or basic UI.**
2. **Payload CMS Best Practices**:
   - When modifying data structures, always edit the files in `src/collections/` or `src/globals/` and regenerate types via the `npm run generate:types` script.
   - Do not bypass the CMS for content. Hardcoded content should be minimized; use Payload collections/globals instead.
3. **Performance First**: For interactive elements, leverage GPU-accelerated CSS (`transform`, `opacity`, `filter`). Keep React re-renders to an absolute minimum by utilizing refs (`useRef`) and Framer Motion's motion values instead of React state (`useState`) for rapidly changing values (like scroll position).
4. **Environment Variables**: The project relies on `.env` variables for Postgres connection and S3 (AWS/Cloudflare R2) storage credentials. Do not expose these in the codebase.
